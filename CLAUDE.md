# OneBase — конфигурация

Это проект конфигурации платформы OneBase (1С-подобная: метаданные YAML + DSL `.os`).

**Инструменты и правила разработки — в `AGENTS.md`** (сгенерирован `onebase ai-guide`,
всегда синхронизирован с версией движка). Перед правкой запросов прочитай раздел
«Запросы — частые ошибки» в `AGENTS.md`.

Быстрый цикл:
- `onebase check` — валидация перед коммитом (exit ≠ 0 при ошибках).
- `onebase describe` — структура этой базы в JSON.
- `onebase ai-guide --output AGENTS.md` — обновить руководство.

## Проекты сверки и репозиторий настроек

- **Проект сверки** (справочник `ПроектыСверки`) группирует источники и настройки: у `Источники`
  и `НастройкиСверки` реквизит `Проект` (подчиненности справочников в onebase нет). Наименования уникальны
  в пределах проекта; объекты без проекта — заведенные до проектов, их переносит обработка `НазначитьПроект`.
  Запуск находит настройку по имени и, если оно есть в нескольких проектах, требует проект
  (`ВыполнитьСверку` параметр `ИмяПроекта`, в `/hs/sverka/run` ключ `"проект"`).
- У проекта может быть свой git-репозиторий настроек на Forgejo: веб-адрес `https://хост/владелец/репо`,
  ветка (пусто — `main`), каталог (пусто — корень), признак «Синхронизировать», токен API — ссылкой
  `file:<путь>` как пароли источников. Завести из командной строки — обработка `НастроитьПроект`.
- Формат (модуль `НастройкиПроекта`): файл на объект — `sources/<имя>.json`, `settings/<имя>.json`; ключи те же,
  что в снимках для `ЗагрузитьНастройки`, всегда все и в одном порядке, отступ 2, многострочные запросы — массивом
  строк. Паролей нет: секрет, не начинающийся с `file:`, выгрузка отвергает. `ЗагрузитьНастройки` понимает и снимок
  `{"источники","настройки"}`, и файл объекта, и каталог рабочей копии; `ВыгрузитьНастройки` пишет каталог.
- Синхронизация (модуль `РепозиторийНастроек`, HTTP API Forgejo, git не нужен): обработки `ПолучитьИзРепозитория`,
  `ОтправитьВРепозиторий`, `ПроверитьРепозиторий` (только чтение) и `POST /hs/sverka/sync`
  `{"проект", "действие": "получить"|"отправить", "заменитьЛокальные"}` (200 / 409 при конфликтах).
  В регистре `СостояниеСинхронизации` — sha и текст файла на момент последней синхронизации. Отправка — один коммит;
  файл, измененный в репозитории после получения, не перезаписывается (конфликт), sha передается и в API.
  Получение не затирает объект, измененный в базе после синхронизации (конфликт; `ЗаменитьЛокальные` — взять версию
  репозитория). Удаление и переименование пока не синхронизируются — только заметки в итоге.
- Нужен `onebase settings set net.enabled вкл`. Тесты: `onebase test --sqlite :memory:` (`ТестНастроекПроекта`).
